Agent Sandbox Architecture

Status: target design. Built so far: the agent VM, the jailed credential proxy and the egress policy for the Anthropic API (HOWTO §9.5). Not built: the inference VM, short-lived per-tool tokens, human approval.

An agent with no separate gateway pod. The VM boundary plus one jailed host-side proxy does the gateway's job. The agent guest holds no credentials and has no network. The GPU sits in a separate inference VM.

Boundaries and what each one stops

BoundaryStopsDoesn't stop
Lean guest kernelA kernel exploit lands in guest ring 0, not host ring 0. Most 2026 LPE trigger paths (io_uring, user namespaces, BPF) aren't compiled in.Bugs in what's left; KVM itself.
Firecracker jailerA VMM escape stays inside a chroot with its own cgroups and seccomp, and no network route.KVM bugs.
vsock only, no NICDirect egress, DNS exfil, the metadata endpoint and the kube API. With the vsock-only kernel profile (VSOCK_ONLY=1), TCP/IP, the NIC driver and packet sockets aren't compiled in either.Exfil through calls the proxy allows.
Host proxyPrompt-injected exfil over permitted calls, through per-tool method/path/size rules, rate limits and a full audit log. No CA has to be planted in the guest.Misuse that fits inside the policy.
Credential brokerTheft. The secret never enters the guest, and tokens are scoped, short-lived and revoked at teardown.Use of a token's authority through allowed calls.
Inference VM splitPCI, the vendor GPU driver and model weights stay out of the agent's guest. If the GPU VM is compromised, it holds no credentials and has no egress.GPU firmware persisting across tenants.
Human approvalIrreversible actions taken on injected instructions.Approval fatigue.

Still open

  • A remote model API remains an allowed path out, because prompt content is data. Local inference in the GPU VM closes it.
  • Firecracker VFIO passthrough was landing in spring 2026 (PR #5870, --enable-pci) but isn't confirmed in a release. Until it is, the inference VM runs on Cloud Hypervisor or QEMU.
  • Shared GPU access (vGPU, MIG across tenants, gVisor nvproxy) would expose the host GPU driver to the guest. The design assumes one dedicated GPU per trust domain.
  • Nothing here bounds KVM. Host patch cadence still matters.
